# Provenance of the shared core

`core/` is canonical for the Treatable apps and is a second copy of reviewed, security-critical code from the Chrome extension (final-plan.md amendment R3). This file records, for every ported file and function, where it came from, what changed, and why. Converging the extension onto `core/` is a later task that needs coordination with the extension's maintainers; `extension/` is not edited here.

- Source commit: `48c569e6ade1803730384870d5cd1cffbf895676` (`48c569e`, branch `codex/treatable-mvp`, "fix: restrict side panel to ClinicalTrials.gov tabs").
- Reviewed state: `extension/SECURITY_REVIEW.md` (review of source `29f126b`, recorded at `48c569e`).
- Ported by task A1a on 2026-10-24. Screening, the offline ZIP lookup, and the outbound transport gate were ported by task A1b on 2026-10-24; their sources (including the scaffold, which the drift check pins the same way) are in the tables below.
- Drift check: `node scripts/drift-check.mjs` compares each source below (by git blob ID at `48c569e`) with a target commit or the working tree and exits non-zero on any change. On 2026-10-24 it reported no drift against this branch and against `codex/treatable-mvp` at `4281bef` (the only upstream change since `48c569e` is `extension/src/demo-panel.tsx`, which is not ported).

| `extension/native/real.mjs` `PreparedRealStore` (`prepare`, `take`, `revoke`, `clear`, TTL timer, `onInvalidate`) | `src/consent/store.ts` (`createConsentStore`) | Semantics kept: one active preparation; pinned, deep-frozen preview; reply is a copy; opaque 32-byte token (43 base64url characters); SHA-256 digest; five-minute expiry with a timer that clears and calls `onInvalidate`; per-operation one-use; failures return nothing. Changed: (1) generic over a pinned subject digest (task A2 decides what it covers) and `take()` requires the current subject digest, clearing on mismatch, so a mutated record set cannot execute old consent; (2) the preparation names the operations it authorizes; (3) the digest is SHA-256 over the RFC 8785 canonical JSON of `{ operations, policyVersion, preview, subjectDigest }` through the Sha256 port, instead of `createHash` over `JSON.stringify({ policyVersion, catalogMetadata, preview })`, so any holder of the preview can recompute it regardless of key order and the bundled-catalog metadata (not ported) is replaced by the subject digest; (4) time, randomness, hashing, and timers come from ports, and expiry uses the monotonic clock; (5) async ports made prepare asynchronous, so a generation counter makes any clear during hashing win over the preparation (`CANCELLED`); (6) `take()` without a live preparation returns `CONSENT_EXPIRED` only when the last one timed out and `INVALID_CONSENT_RECEIPT` otherwise (the extension always said `CONSENT_EXPIRED`), for accurate user messages; (7) token and digest comparisons are constant-time; (8) port outputs (digest format, token length, all-equal bytes) are validated; (9) `close()` permanently disables the store at `endSession`. Kept on purpose: when the five minutes end, work still running is aborted, as in the extension. |

| `extension/src/core.ts` `nearestSite` | `src/screening.ts` `nearestSite` (and `nearestDistanceMiles`) | Same choice: the nearest located study site, the first listed site when coordinates are unknown, and the first site again when nothing is located. | `extension/native/transport.mjs` outbound request rules (the guard inside its `request()`) | `src/transport-gate.ts` (`toTransportRequest`, `checkTransportRequest`, `guardTransport`, `guardCorePorts`) | Same invariants, moved out of the transport's own implementation into core code a transport port cannot replace: the endpoint path allowlist and GET/POST/DELETE methods (`INVALID_ENDPOINT`), the exact `https://api.openai.com` origin pin (no subdomains, ports, userinfo, query strings, or fragments), the request-body cap (`MAX_OUTBOUND_BODY_BYTES`, checked by the builder on serialized JSON and again by the guard on the bytes about to leave), `OpenAI-Beta: agents=v1` required on agents paths and forbidden everywhere else, `Content-Type: application/json` exactly when a body is sent, and `Authorization` only `Bearer ` plus a contract-shaped key or absent. Added: the guard re-validates every request independently of the builder and rebuilds a frozen request (canonical header names, a fresh copy of the body) before the port sees it, and it is wired inside `createCore` (`guardCorePorts`), so hand-crafted callers and hostile or compromised transport ports cannot widen the invariants and a rejected request never reaches the port; header values are one line of printable ASCII (a CRLF-smuggled header cannot exist); unknown or duplicated headers are rejected, not dropped. `toTransportRequest` is the only request constructor core callers need (the replacement for transport.mjs's own request assembly). Response-side caps and error mapping stay with the provider work (task A4). |

## Not ported

- Chrome-only code: `validateOrigin`, `EXTENSION_ID`, `HOST_NAME`, native messaging manifests, the installer (`install.mjs`). The import-graph test bans these names in `core/src`.
- macOS Keychain access (`credentials.mjs`, `credential.swift`): replaced by the `credential.request` protocol; each platform stores the key in its own credential store (task A6b and the platform tasks).
- The 2,000-study snapshot, public catalog, demo fixtures, and BM25 pipeline (live ClinicalTrials.gov search replaces them).
- Provider runners (`provider.mjs`) and the response side of the HTTPS transport (`transport.mjs` response caps and error mapping): task A4. The outbound rules of `transport.mjs` were ported by task A1b into `src/transport-gate.ts`; the transport implementation itself stays host code (`node/ports.node.ts` is the Node reference). Both source files stay in the drift check because they are security-critical.
- The scaffold's patient-facing explanation pipeline (warnings, note strings, call scripts, `scoreStudyMatches` narration): task A5 owns user-facing language. The scaffold's `openTo` toggles and expanded-access visibility are a host preference, not a core rule.
